CITPL CRICKET LEAGUE PLATFORM

Complete Technical Architecture, Database Schema, API Structure & UI Blueprint

---

1. PROJECT ARCHITECTURE

Build CITPL as a full-stack web application with three major layers:

Frontend

Recommended:

- Next.js
- React
- TypeScript
- Tailwind CSS
- Component library such as shadcn/ui

Backend

Recommended:

- Next.js API routes or separate Node.js backend
- TypeScript
- REST APIs
- WebSocket/Socket.IO for real-time auction and live scoring

Database

Use:

- PostgreSQL

ORM:

- Prisma or Drizzle ORM

File Storage

Use cloud/object storage for:

- Player photos
- Team logos
- Documents
- Payment screenshots if required

Authentication

Use secure authentication with:

- Email/mobile login
- Password or OTP
- Session management
- Role-based authorization

57. AUCTION TRANSACTION SAFETY

Auction bids must be processed server-side.

When bid arrives:

1. Verify user
2. Verify captain role
3. Verify team ownership
4. Verify auction is LIVE
5. Verify player is LIVE
6. Verify bid > current bid
7. Verify sufficient purse
8. Verify squad limit
9. Save bid
10. Update current bid
11. Broadcast bid

All of this should happen atomically.

---

58. LIVE SCORE TRANSACTION SAFETY

When a ball is submitted:

1. Verify scorekeeper
2. Verify match assignment
3. Verify match is LIVE
4. Validate striker
5. Validate bowler
6. Validate innings
7. Save ball event
8. Recalculate innings
9. Update score
10. Update player statistics
11. Broadcast event

Avoid duplicate ball submissions.

Use unique event IDs or idempotency keys.

---

59. IMPORTANT: SINGLE SOURCE OF TRUTH

Do not manually maintain:

Player runs
Team runs
Points
NRR
Bowler economy
Player strike rate

These should be calculated from match events.

For example:

BALL EVENTS
     ↓
INNINGS SCORE
     ↓
MATCH SCORECARD
     ↓
PLAYER MATCH STATS
     ↓
TOURNAMENT PLAYER STATS
     ↓
LEADERBOARD

This prevents inconsistent statistics.

62. DEVELOPMENT RULE

Do not build the application as a collection of disconnected pages.

The entire platform must be connected through one database and one consistent permission system.

For example:

If Rahul is sold to Team Warriors for ₹1,500 during auction:

The system must automatically update:

Rahul → Team Warriors

Team Warriors:
Spent +₹1,500
Remaining Purse -₹1,500

Auction:
Rahul = SOLD

Captain Dashboard:
Rahul appears in squad

Public:
Rahul appears in Team Warriors squad

Statistics:
Rahul is now associated with Team Warriors

Similarly, if Rahul scores 45 runs:

Ball events
     ↓
Match score
     ↓
Rahul's match stats
     ↓
Rahul's tournament stats
     ↓
Team total
     ↓
Leaderboard

No manual duplicate updating should be required.
